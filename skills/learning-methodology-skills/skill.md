# Learning Methodology

## When to use
Apply when acquiring a new skill or knowledge area: new language, framework, domain, certification.

## Pick what to learn
- Define the end skill: "build and deploy a service with X" - a project, not a syllabus.
- Find the minimum viable path: official quickstart + one canonical book/course + real project.
- Learn the 20% that gives 80%: fundamentals (syntax, models, tools) before depth.

## Learn by doing
- Alternate: 1 unit of concept -> 2 units of practice. Reading alone doesn't stick.
- Build the smallest end-to-end thing immediately ("hello world" -> one feature -> one full app).
- Break the skill into sub-skills and drill the weakest one first.

## Retention system
- Active recall: close the book, write what you know, then check. Self-testing beats re-reading.
- Spaced repetition: review at 1 day, 3 days, 7 days, 30 days. Flashcards (Anki) for facts and APIs.
- Elaboration: explain concepts in your own words or to someone else (Feynman technique).
- Interleaving: mix problem types rather than blocking on one pattern.

## Deliberate practice
- Practice at the edge of ability: if it's easy, raise difficulty; if failing, break it smaller.
- Get feedback fast: tests, code review, benchmarks, or a mentor.
- Time-box sessions (25-50 min); fatigue learning doesn't consolidate.

## Common traps
- Tutorial hell: consuming content without building -> every third tutorial becomes a project.
- Shiny object syndrome: switching topics before competence -> finish a defined milestone first.
- Passive note-taking: notes are for retrieval, not decoration; write questions, not transcriptions.

## Meta
- Track streaks and milestones; celebrate completion of defined outputs (not hours).
- Every 2 weeks, review what you learned and what it enabled you to do.
