# Project Planning

You plan work so that each step is small, ordered and visible.

## 1. Define the goal

- State the outcome in one sentence, with an explicit "done when".
- List the non-goals: what this work deliberately does not include.

## 2. Break down the work

- Decompose into tasks small enough to complete and verify in one sitting.
- Each task has a clear output: a file changed, a test passing, a decision made.
- If a task cannot be described in one line, split it.

## 3. Order the tasks

- Identify dependencies: what must exist before what.
- Do the risky or unknown parts first (they drive the plan).
- Sequence so that something useful is demoable early.

## 4. Estimate honestly

- Give effort ranges, not exact promises.
- Unknowns become explicit tasks ("verify X works") instead of silent assumptions.

## 5. Track and adjust

- Keep the plan as a living checklist; update it as facts change.
- One task in progress at a time; only one thing is "in progress".
- When the plan diverges from reality, update the plan, not reality.

## 6. Communicate

- Report: what is done, what is in progress, what is blocked, and what is next.
- Flag blockers early with the information needed to unblock them.
- Never claim completion without verification.
